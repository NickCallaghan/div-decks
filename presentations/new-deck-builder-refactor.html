01

Section

The Problem

Why deck generation felt slow.

FOUND DURING ANALYSIS

The model was re-typing fixed code on every run

  • ~280 lines of core CSS — identical between decks
  • ~140 lines of SlideEngine JS — the skill literally said "DO NOT modify this engine"
  • Output tokens dominate LLM latency, so this is the largest single cost
  • Two duplicate sources of truth (template embedded what the references described)
  • Directly violates the global rule: "offload to deterministic process where possible"

BEFORE

Per-deck output

CSS lines 280 verbatim
Engine lines 140 verbatim
Variable ~25% ↓ signal
Sources of truth 3 drift risk
02

Section

The Fix

Move deterministic output into deterministic code.

NEW LAYOUT

A 80-line Node script replaces the boilerplate

  • bin/build-deck.mjs — zero-dep Node ESM, discovers themes from disk
  • assets/core.css — single source for the structural CSS
  • assets/slide-engine.js — single source for the engine
  • themes/{midnight,warm-signal,terminal,swiss}.css — four built-ins, brand skills add more
  • templates/base.html — five injection markers, nothing else

$ what the model now invokes

node ./bin/build-deck.mjs \
  --theme terminal \
  --slides /tmp/slides.html \
  --title "Q2 Roadmap" \
  --out ./presentations/q2-roadmap.html

# stdout: /Users/.../presentations/q2-roadmap.html

BEFORE

Model writes everything

~1,000 lines of HTML output per deck, 80% of which is fixed boilerplate.

AFTER

Model writes only sections

~250–400 lines of slide markup. Builder injects engine, core CSS, theme.

AFTER

Same deck, different shape

Boilerplate from LLM 0 ↓ from 420
Sources of truth 1 ↓ from 3
Themes shipped 4 extensible
Builder deps 0 pure node
